# Security policy

## Reporting a vulnerability privately

Please report security vulnerabilities through [GitHub private vulnerability reporting](https://github.com/liusha-com/resumv/security/advisories/new). A GitHub account is required. Do not disclose vulnerabilities, exploit details, credentials, or private resumes in public issues or pull requests.

Include the affected version or commit, reproduction steps using fictional data, expected and actual behavior, and potential impact. Remove personal information and secrets from attachments. Coordinate public disclosure with the maintainers after a fix is available.

If the private reporting form is unavailable, open a public issue **only requesting that private vulnerability reporting be enabled**, without any vulnerability details or sensitive attachments. Wait for a private channel before sharing technical information.

## Supported versions

Security fixes target the latest code on `main`. Update self-hosted deployments to the latest revision; older snapshots do not receive separate security backports.

## Ordinary feedback

Use [GitHub Issues](https://github.com/liusha-com/resumv/issues) for non-sensitive bug reports, feature requests, and content corrections. Use fictional or anonymized examples.

## Maintainer setup

Enable **Private vulnerability reporting** in the repository's Settings → Security → Advanced Security before publishing this policy as an available reporting channel. The reporting URL alone does not enable the feature.
